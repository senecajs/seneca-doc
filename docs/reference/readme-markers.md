# README markers and generated sections

The `seneca-doc` tool replaces the text between pairs of HTML comments
in `README.md`. Each pair has a name:

```markdown
<!--START:name-->
(replaced)
<!--END:name-->
```

The markers themselves stay, so the command can be run again. A pair
is matched as a whole (`<!--START:name-->` up to the first
`<!--END:name-->`, across lines); pairs without generated content, and
generated content without a pair, are ignored. Dollar signs in the
generated text are inserted literally.

Pairs are matched anywhere in the file, including inside code blocks.
To show the markers in a README code block, use a name that is not
generated, such as `<!--START:name-->`, as the README of `@seneca/doc`
does.

## `options`

A level two heading `## Options` and one bullet per option:

```markdown
* `currency` : string <i><small>"EUR"</small></i>
* `tax.rate` : number <i><small>0.2</small></i>
* `name` : string <i><small>required</small></i>
```

The options come from the `options_shape` of the `describe:plugin`
reply, that is, from the plugin `defaults` (Seneca 3 records the shape
when it validates options with Gubu; otherwise `@seneca/doc` builds it).
Nested options are listed as `parent.child`, each with its Gubu type
and then `required`, or its default value in JSON when that is a
string, number or boolean (optional values made with `Skip` show no
default); properties ending in `$` (directives such as `init$`) are
left out. When the plugin record carries a Joi schema as
`options_schema`, that schema is rendered instead, with a note on how
to set options (Seneca 3.38 and 4 record `null` there). Without options
the section says `*None.*`.

## `action-list`

A heading `## Action Patterns` and a sorted bullet list linking to the
descriptions:

```markdown
* [role:shop,cmd:price](#-roleshopcmdprice-)
```

Patterns are rendered with top level properties first (`role`, `sys`
and the `-t` names, see [Command line](command-line.md#flags)), then
the others alphabetically. The link anchor is the pattern without any
non word character, between dashes, which matches the anchor GitHub
generates for the description heading.

## `action-desc`

A heading `## Action Descriptions` and, for each action in the same
order, a heading ``### &laquo; `pattern` &raquo;`` followed by either the
content of the file named by the action's `path`, or:

1. the `desc` (or `*None.*`);
2. `#### Examples`, when there are examples: `` `<pattern>,<key>` `` and
   the description of each;
3. `#### Parameters`, when the action has rules: for a pattern with
   Gubu rules, each rule's type in italics and
   ``(optional, default: `value`)`` when not required; otherwise each
   `validate` rule, as Joi
   type with `required` or the default and the `description`, or with
   `util.inspect` for non Joi values;
4. `#### Replies With` and the `reply_desc` as a fenced block, when
   present.

Each action ends with a `----------` rule.

## `SECTION:<name>`

The content of the file named by `sections.<name>.path` in the doc
definition, inserted as is (see
[Doc definition](doc-definition.md#sections)).

## Example

The README of the tutorial project,
[docs/examples/shop/README.md](../examples/shop/README.md), contains
only the markers. After `npm run doc` (in the repository:
`node ../../../bin/seneca-doc-exec.js` in that folder) it reads, in
full:
